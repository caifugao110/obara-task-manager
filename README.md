# Obara 任务管理系统

![License](https://img.shields.io/badge/License-MIT-green) ![Platform](https://img.shields.io/badge/平台-Windows%20%7C%20跨平台-lightgrey) ![Socket.IO](https://img.shields.io/badge/实时协作-Socket.IO-010101?logo=socket.io&logoColor=white)

Obara 任务管理系统是一款本地部署的 Excel 风格任务与工时管理工具，集成任务录入、工时统计、状态追踪、焊枪台账、设计规范知识库检索与问答、报表查询、权限控制与数据导入导出等能力，支持多人实时协作、离线浏览与操作审计。

## 快速开始

### Windows 一键启动

```bat
start.bat
```

`start.bat` 会隐藏窗口运行（不打开浏览器），依次执行：检查 Node.js 版本 → 检查并释放 5000/5173 端口 → 按需安装依赖 → 后台启动前后端，日志输出到 `logs/` 目录。**启动脚本不会自动拉取代码**：自动 `git pull` 存在供应链风险（拉取即执行），已移除；代码更新请人工确认后手动执行 `git pull`，再运行本脚本。

启动后访问：

- 前端：http://localhost:5173
- 后端：http://localhost:5000

> `start.bat` 强制要求 Node.js 22+（better-sqlite3 13、joi 18、pdf-parse 2.4 在更低版本上无法运行），版本过低时会直接报错退出。
> 首次部署可通过环境变量 `DEFAULT_ADMIN_USERNAME` 和 `DEFAULT_ADMIN_PASSWORD` 配置默认管理员账号，启动时自动创建超级管理员（仅当不存在超级管理员时生效）。未设置 `DEFAULT_ADMIN_PASSWORD` 时，首次启动会自动生成随机密码并**仅在后端控制台输出一次**（`start.bat` 隐藏窗口运行时输出在 `logs/backend.log`，丢失后可按 [DEPLOYMENT.md](DEPLOYMENT.md) 的「忘记超级管理员密码」FAQ 处理），请立即记录并登录修改（该账号同时被标记为需强制修改密码）。

### 首次部署检查清单

1. 安装 Node.js 22+（推荐 22 LTS）、npm 10+ 和 Git。
2. 执行 `npm run install:all` 安装根目录、后端和前端依赖。
3. 复制 `backend/.env.example` 为 `backend/.env`，必须修改 `JWT_SECRET`（缺失将导致服务无法启动），并配置 `CORS_ORIGIN`。
4. 可选：配置 `DEFAULT_ADMIN_USERNAME` 和 `DEFAULT_ADMIN_PASSWORD` 设置默认管理员账号（首次启动时自动创建；不设置密码时会生成随机密码，仅在控制台显示一次）。
5. 使用 `start.bat` 或 `npm run dev` 启动，确认前端 http://localhost:5173 和后端 http://localhost:5000 可访问。
6. 登录后进入系统设置，确认多设备登录、页面权限和数据导出功能符合部署要求。

### 手动启动

```bat
git clone https://gitee.com/caifugao110/obara-task-manager.git
cd obara-task-manager
npm run install:all
npm run dev
```

> 仓库同时镜像在 GitHub：`https://github.com/caifugao110/obara-task-manager.git`，可任选其一。GitHub 版本会触发 CI 自动构建控制台 EXE 并部署文档到 GitHub Pages。
> 根目录 `package.json` 的 `engines` 字段仍声明 `node>=18`，仅供兼容提示；实际依赖（`better-sqlite3@13`、`joi@18`、`pdf-parse@2.4`）要求 **Node.js 22+**，请以 22+ 为准（`start.bat` 会强制校验，低于 22 直接报错退出）。

## 当前功能

### 主页面

- 按设计人员和日期录入任务。
- 支持设计计划、出差、事假、休假、病假等任务类型。
- **任务内容复选框**：任务编辑框中可勾选「确认图 / 设计 / 确认图修改 / 设计变更 / 既制审图」为任务名追加对应后缀，五项互斥；勾选「设计变更」「既制审图」本身不写总工时，填写枪名后按「默认工时规则」中配置的固定工时（默认 1.5h / 0.5h，不分 C/X、不套用枪名专用规则）逐个枪名自动计算，没有枪名时由用户手动输入总工时。
- **切换任务内容同步工时**：任务已有枪名（且已带工时）时，切换「任务内容」会按新内容重算各枪名工时，总工时随之更新为枪名工时之和。
- 新增任务时默认标记颜色为浅绿（`#86efac`）；开启系统设置「设计计划标记颜色随机」后，每次新增任务会从预设颜色中随机选择一个标记颜色（不含「无」）。
- 任务类型切换时会保留已填写的任务内容、枪名、枪名工时、出差地点/客户等临时输入。
- 枪名存在时，该枪名工时不能为 0。
- 管理员悬浮任务时可查看创建者、创建时间、最后修改者、最后修改时间。
- **所有任务内容的修改（包括枪名的编辑、复制、删除）都会记录最后修改者和最后修改时间。**
- 选中任务后，按住 `Ctrl`（Mac 上为 `Cmd`）可选择多个任务。
- 多选任务支持拖拽移动、`Ctrl+X` 剪切、`Ctrl+C` 复制、`Ctrl+V` 粘贴。
- **按住 `Ctrl` 键拖拽任务到目标单元格，会执行批量复制操作而非移动操作。**
- **拖拽落点由指针命中的位置决定**（移动与复制一致）：拖拽过程中指针扫过目标单元格内的某条主任务时，落点为**该任务之前**（插入其上方）；未命中任何任务时追加到该单元格末尾。指针划过源单元格自身时不产生任何预选中标记。
- **拖拽预选中与重复拦截**：目标单元格显示插入位置标记线（命中任务上方或单元格末尾，4px 高，可放置为绿色 `#16a34a`、不可放置为红色 `#ef4444`）；若目标单元格已存在**内容完全相同**的主任务，标记线转为红色，拖拽浮层边框转红并浮出红色「重复任务」徽标，光标变为 `not-allowed`，松手时整体拒绝并提示「目标已存在内容完全相同的主任务「xxx」，拒绝复制/拒绝移动」。
  - 「内容完全相同」的判定字段：`taskName`（trim 后严格相等）、`hours`、`leaveType`、`guns` 数组长度与逐项 `name`/`hours`（**顺序敏感**）；任务颜色、枪名颜色和 `colorMarkedBy` 不参与比对。
  - 复制时检查全部待复制任务（多选时以整个多选集合为对象，经 `POST /api/tasks/item/batch` 一次性提交）；移动时排除「已经在目标单元格中」的选中任务，只对真正会被移过去的任务检查（逐条 `POST /api/tasks/move`）。任一重复即整批拒绝。
  - 拖回自己所在的单元格：移动操作静默无动作（不提示），复制操作则会真复制一份（并同样受重复检查约束）。
  - 拖放结果可用 `Ctrl+Z` 撤销、`Ctrl+Y` 重做（复制记为一次批量新增）。
- **主任务支持「上移」「下移」排序**：任务悬浮工具栏提供上移/下移按钮，按钮固定在行右侧，在同一天单元格内与相邻任务交换顺序（跳过被过滤隐藏的空任务），操作可撤销。请假（事假/休假/病假）与出差类主任务同样支持排序，其状态徽标居中、上下移按钮位于行右端。
- **单个枪名支持跨主任务拖拽移动**：管理员拖拽枪名行右侧拖动手柄，可将单个枪名（连同其工时）移动到**任意设计人员、任意日期**的任意设计计划主任务；落在目标主任务的某条枪名上则插入到该枪名之前，否则追加到末尾。目标主任务已存在同名枪名、目标主任务没有任何枪名、或目标为请假/出差类任务时拦截并提示；源主任务最后一个枪名被移走时源主任务一并删除（撤销时自动重建）。移动前会先落盘源/目标单元格的防抖编辑内容，避免未保存输入丢失。
- **枪名可拖到「没有主任务」的落点上自动新建主任务**：落在**没有任何主任务（当前筛选下可见）的空白单元格**上时整格绿色高亮、浮层提示「松手新建主任务」，松手后按源主任务的名称在该格新建一个主任务（工时 0）再把枪名移入；落在**已有主任务的单元格最下方的加号**上时仅加号高亮、浮层提示「松手在下方新建主任务」，新主任务追加到该格末尾。新建主任务的完成状态跟随被移动的枪名（枪名已完成则同样标白，未完成则沿用枪名颜色；枪名无色时取源主任务颜色，源主任务也为白色时随机取一个非白颜色并同步染该枪名，避免未完成的枪名落到表示「已完成」的白底上）。两种新建均可撤销：撤销把枪名移回后，这个新建的空主任务会自动删除；重做时按记录的名称重新新建。松手回到**源单元格的空白处**视为取消（不提示）；落点在已有主任务的格子里、但既没压住任务行也没压住加号时提示「该位置没有主任务，请拖到已有主任务上，或拖到该格最下面的加号上新建主任务」。
- **同一主任务内的枪名顺序通过枪名行的「上移」「下移」箭头调整**（连同工时一起换位）；拖拽手柄不承担同任务内排序。枪名移动与排序均支持 `Ctrl+Z` 撤销 / `Ctrl+Y` 重做。
- **枪名拖拽的实时反馈**：拖拽路径扫过的目标主任务整体描边变色表示预选中（绿色=可放置，红色=目标已存在同名枪名或目标主任务没有任何枪名）；目标重名时拖拽浮层正上方显示红色「重复枪名」提示且禁止放置，目标没有枪名时同一位置显示红色「目标无枪名，不能移入」。指针扫过源主任务自身时不高亮。
- **枪名移动的拦截提示原文**：落点仍在源主任务内时提示「同一主任务内请使用枪名行的上移/下移箭头调整顺序」；目标主任务已存在同名枪名时提示「目标主任务已存在枪名「xxx」，无法移动」；目标主任务没有任何枪名时提示「目标主任务没有枪名，不能移入枪名」（这类行只有主任务自身的内容，塞入枪名会让主任务工时被枪名工时取代）。
- **多人协作的编辑会话已下沉到「主任务」粒度**：同一设计人员同一天的**不同主任务允许多个用户同时编辑、互不干扰**；只有当同一个主任务（或旧版整格会话）已被他人占用时才互斥。
  - 会话标识：前端为 `designerId__date__itemId`，后端为 `designerId::date::itemId`；`itemId` 为空代表旧版「整格会话」（兼容未升级的客户端），仍会独占整个单元格，并保留整格红色罩层提示。
  - **同一用户同时只能持有一个会话**：切换到别的主任务会自动释放自己之前的会话（服务端广播 `user_stopped_editing`）。
  - 他人占用时的提示位置：主任务级会话在**该主任务行**内显示红色脉冲徽标「AAA 正在编辑」；`colorMark` 模式按 `gunIndex` 再精确到具体**枪名行**（显示「AAA 正在修改任务状态」并隐藏该枪名行的悬停操作按钮）；`gunIndex` 为空时标记整个主任务行。
  - 操作被拦截时的 Toast 原文：`AAA 正在编辑该任务，暂无法操作` / `AAA 正在修改该任务的完成状态，暂无法操作`；整格级拦截则为 `AAA 正在编辑该区域，暂无法操作`。
  - **新增主任务不申请编辑会话**，也不受他人主任务级会话拦截；粘贴、多选剪切复制等操作按各自涉及的主任务逐条校验。
  - 拖拽移动/复制主任务时：**源主任务按主任务粒度校验**，目标单元格只做整格级（旧版会话）校验——因为在他人主任务之间插入新位置并不修改那个主任务。
- **任务变更的实时刷新策略**：编辑者保存后按「设计人员 + 年月」发送增量广播，服务端从数据库读取该工时表的最新数据再广播，其他客户端只本地合并受影响的表（仅限当前查看月份），不必重新拉取整月数据；批量操作、跨人员移动、工作日设置变更等影响范围不明确的场景退化为全量刷新信号。无编辑权限的只读客户端把全量刷新合并为 3 秒一次，页面在后台时挂起、切回前台再补刷一次，避免多人在线时反复全量拉取。服务端对该事件按连接限流（10 秒 20 次），超限时不报错而是记录最后一次变更坐标、窗口结束后补发一次刷新信号，保证连续切换状态时其他客户端的最终状态不丢（详见 API 文档「限流与补发」）。
- 底部统计会显示本月任务条目、周末加班、员工出差和员工请假汇总。
- 主页面日期表头支持管理员设置工作日覆盖规则：一般管理员和超级管理员将鼠标悬停在日期上时，可勾选“将今日设为普通工作日”或“将今日设为周末加班日”。未勾选时按自然周六/周日判断；勾选后主页面周末底色、底部周末加班统计、工时管理统计和工时导出表均按覆盖后的有效工作日/周末计算。

### 离线模式

- 离线检测双通道：
  - 通道一（全页面）：浏览器断网，靠 `navigator.onLine` 与 `online`/`offline` 事件。
  - 通道二（全页面）：后端进程停止但浏览器仍在线时，由**全局后端心跳**统一检测并广播全局 `server-unreachable` 事件（恢复时广播 `server-online`），**所有页面均订阅该事件**。心跳在 `frontend/src/main.tsx` 启动（实现在 `frontend/src/services/api.ts`），每 5 秒探测一次无需登录的 `GET /api/auth/session-policy`（该接口不写操作日志，不会污染审计；页面处于后台标签页时跳过探测，切回前台立即补一次），把「发现停服」与「发现恢复」都压到一个心跳周期内，登录页等空闲页面也能及时感知。
  - 通道二的停服判定不只看网络层失败（无响应 / `ERR_NETWORK` / 超时），也覆盖**代理在后端停止时回的非 JSON 5xx**（开发环境 Vite 代理返回 `text/plain` 空 body 500，生产 nginx 等通常为 502/503/504）——后端自身抛出的带 `application/json` 错误体的 5xx 属于应用层错误，不会误判为不可达。不可达期间每轮心跳都会重新广播 `server-unreachable`，晚于停服挂载的页面也能立即进入离线态。
- 覆盖页面：主页面（含 localStorage 缓存浏览）、管理后台、任务报表、工时管理、系统设置、焊枪台账、状态追踪，均显示橙色横幅「当前处于离线模式，此页面禁止编辑」并拦截所有写操作（提示「当前离线，禁止编辑」）。
- 登录页与修改密码页同样离线禁用：两者监听 `online`/`offline`/`server-unreachable`/`server-online`，离线时输入框与提交按钮禁用，顶部琥珀色提示「当前网络离线，无法登录，网络恢复后自动解除限制」/「当前网络离线，无法修改密码，网络恢复后自动解除限制」，提交时提示「当前网络离线，无法登录，请待网络恢复后重试」/「当前网络离线，无法修改密码，请待网络恢复后重试」。
- 任务报表、工时管理、操作日志在离线时进一步禁用交互控件（月份切换、刷新、开关、仕样号/枪名输入框、导出按钮等），容器加灰度样式；任务报表的仕样号/枪名搜索与工时管理的数据拉取在离线时直接跳过，并提示「当前离线，禁止编辑」。
- 主页面额外支持离线缓存：首次断开时自动保存当前数据到浏览器 localStorage，刷新页面后如果后端仍不可用，直接使用缓存数据浏览；缓存仅用于离线浏览，不会覆盖服务器数据。
  - 缓存**只在离线状态下写入**（在线时数据以服务端为准，不再每次变更都全量写 localStorage，避免他人每次编辑都触发本地序列化开销），离线期间的连续编辑按 800ms 防抖合并写入；断网瞬间由 `offline` 事件与 Socket `connect_error` 即时补写一次。
  - 缓存写入失败（如 localStorage 配额不足）不影响在线功能。
- 页脚状态圆点共三态：已建立实时连接且在线为绿色「就绪」；未登录/无 token（无实时更新）为琥珀色「需手动刷新获取最新状态」；离线为红色/琥珀色「离线」。
- 离线期间的重连探测：停服发现由全局心跳负责；已进入离线态的管理后台、任务报表、工时管理、系统设置、操作日志每 5 秒轻量探测 `/api/auth/validate`，后端恢复后由响应拦截器广播 `server-online` 并自动重新加载最新数据、恢复编辑能力；主页面/状态追踪/焊枪台账/设计规范知识库由全局心跳与 Socket 重连触发恢复刷新。
- 焊枪台账离线时自动关闭所有管理弹窗，表保持只读可打开，网络恢复后重新拉取台账并重新申请当前表的编辑锁。

### 焊枪台账

焊枪台账页面（`/gun-ledger`）用于管理焊枪编号台账，采用**分类 → 表 → 行**三级结构。默认分类 `X2C`、`X2C-V2`、`X2C-V3`、`GLOBAL`、`PSW`、`IT`、`ROBOT`、`EQ`、`TOYOTA`，每个分类下可包含多张表，每张表由多行组成，行字段包括：序号、焊枪名、客户、时间、担当、备注。

#### 分类与表管理

- 默认分类 `X2C`、`X2C-V2`、`X2C-V3`、`GLOBAL`、`PSW`、`IT`、`ROBOT`、`EQ`、`TOYOTA` 不允许删除；管理员可新增/重排分类，超级管理员可删除非默认分类（会连同其下所有表一并删除）。
- 「分类」与「表格列表」标题栏提供**恢复默认排序**按钮（仅超级管理员可见，需二次弹窗确认）：分类恢复为系统默认顺序，自定义分类排在默认分类之后；表格恢复为该默认分类的内置表名顺序，自定义表格排在默认表之后（自定义分类下该按钮禁用）。
- 管理员可在分类下新增表、重命名表、重排表顺序；超级管理员可删除表。
- 一般管理员可以看到删除分类和删除表的按钮，但点击时会提示「删除分类属于高风险操作，需要超级管理员权限，请联系超级管理员删除」并阻止删除。
- 分类名限 1-30 字符且不含 `/`、`\`；表名限 1-50 字符，同一分类下表名唯一。

#### 行编辑与焊枪名自动取号

- 管理员打开某张表即获取该表的**独占编辑锁**（见下文「表级编辑锁」），可对行进行增删改；保存时行序号会被后端强制重排为严格连续的 `1..N`，杜绝跳号。
- 焊枪名支持**自动取号**：每张表可配置焊枪名生成规则 `{ enabled, prefix, start, pad }`，焊枪名 = `prefix + String(start + 序号 - 1).padStart(pad, '0')`。
  - 未单独配置规则的表，使用前端内置默认规则（按分类+表名匹配，如 `X2C/SRTC` → `SRTC-2C00000` 起）；无匹配则不自动取号。
  - 规则由超级管理员在「台账初始化」面板中按表配置，保存后通过 Socket.IO 广播。
- **「台账初始化」面板（仅超级管理员）为两级弹窗**：
  - 第一级为分类选择视图：列出所有分类卡片（每张卡片可单独「初始化本分类」），顶部有红色「一键初始化全部表格」按钮并显示分类数/表数/行数合计。
  - 第二级为分类详情视图：逐表展示规则卡片（取号开关/前缀/起始编号/补零位数/保存规则/单表初始化），顶部有「一键初始化本分类全部表格（N）」。
  - 批量初始化前弹出红色高危二次确认框；范围为单表、整个分类或全部分类。
  - **初始化语义：删除范围内所有表的全部真实行（`rows=[]`，连同焊枪名、客户、时间、担当、备注一并删除，不可恢复），各表恢复为全新状态**；前端随后只渲染 10 个预留行（序号 1-10），预留行枪名按生效规则（表级 `gunNameRule` → 前端内置默认模式）展示为该表的 10 个原始焊枪名，未启用自动取号时预留行枪名为空。
  - 范围内任一张表正被他人编辑时整体拒绝（`409`，返回 `locked` 数组列出被占用表与持有人），不做部分初始化；一次写入数据库，并逐表广播 `update_rows`（`rows: []`）。
- 焊枪名编辑只影响当前行，不改变行顺序；行按 `serialNumber` 稳定排序，编辑时输入框不会因重排而重建失焦。
- **焊枪名唯一性校验**：保存表行时后端会校验同表内焊枪名不可重复（空值不计），存在重复时返回 `409` 并列出重复的序号位置。
- **焊枪名编号不可修改、前后可自由编辑**：有生效焊枪名规则的表，非空焊枪名的编号必须与规则计算值一致，手动修改编号会被拒绝（返回 `400`）；前缀可自由编辑，编号之后也可继续追加后缀（如 `SRTC-2C15015` → `SRTC-2C15015L` → `SRTC-2C15015-EL` → `SRTC-2C15015L-WL`），编号被自动校正为规则值、前后文字原样保留。
- **向下复制功能**：编辑表行时可点击「向下复制」按钮，将当前行的客户、时间、担当字段复制到下方指定数量的空行；**下方行的焊枪名会继承当前行焊枪名的前缀与后缀，仅编号替换为目标行按规则计算的编号**（前缀 + 目标行编号 + 当前后缀，即整列焊枪名仅编号不同），快速批量填入重复信息；无生效取号规则或焊枪名无法拆分时保留目标行原焊枪名。
- **枪名天蓝色标识**：已被主任务使用的焊枪名在表格中显示为天蓝色加粗（数据来源 `GET /api/tasks/used-gun-names`）。台账页在页面加载、Socket 重连、收到 `task_refreshed` 广播及网络恢复时自动重新拉取该集合，主页面任务变更后其他客户端的天蓝色标识实时更新。

#### 表级独占编辑锁

- 每张表同一时刻只允许一名用户编辑（按 `userId` 判定，同一用户多标签页共享一把锁）。
- 打开表时通过 Socket.IO 申请锁；被他人占用时无法打开，并提示当前编辑者姓名。
- 锁申请、行取号与心跳续期三个 Socket 事件仅 `admin`/`superadmin` 可用（服务端角色校验，普通用户构造客户端也会被拒绝）；普通用户前端本身不发送锁请求。
- 锁通过 Socket 生命周期 + 心跳维持：客户端（仅管理员、非只读打开的表）每 20 秒发送一次 `gun_ledger_table_heartbeat` 续期（服务端 TTL 60 秒）；断开连接移除引用，引用归零即释放；超过 60 秒未续期且已无存活连接的僵死锁由后台每 30 秒扫描清理一次。
- 持有者完成编辑或切换表时释放锁；表被删除/分类被删除/导入覆盖时会强制释放锁。
- **只读打开模式**：当表被他人锁定无法获取编辑锁时，可点击「只读打开」按钮以只读方式查看表内容（不申请表级锁，禁用所有编辑控件）。
- 未取得编辑锁的用户只能以只读方式查看表内容。
- **普通用户只读模式**：开启「普通用户」开关后，普通用户可进入页面浏览全部分类/表/行，顶部显示「当前为只读模式」提示条，无新增/删除/导入/初始化等任何编辑入口，点表不申请表级锁（被管理员锁定的表自动以只读方式打开）。该提示条仅在在线且非管理员时显示，离线时被橙色离线条取代（两条提示互斥）。

#### 默认担当人员

- 系统内置默认担当人员名单（`张啸`、`张明`、`陈青松`、`陈大仪`、`翟世学`、`朱海洋`），作为「担当」列的下拉候选。
- 超级管理员可在「台账初始化」面板中修改默认担当人员，也可一键重置为系统默认。

#### 默认工时规则（仅超级管理员）

- 焊枪台账页面工具栏提供「默认工时规则」按钮（时钟图标），打开弹窗后分两个层级：第一级用三个页签分别展示「机型回退规则」「固定任务工时」「表专用规则」，第二级按分类逐表编辑专用工时。
- 每张表可分别配置「确认图 / 确认图修改 / 设计」三类任务的默认工时（0-24h，三个值必须全部填写或全部留空；留空的自建表运行时继续回退）。
- 「固定任务工时」页签配置「设计变更」（默认 1.5h）与「既制审图」（默认 0.5h）的工时，**不区分枪名机型 C/X，也不套用任何表专用规则**。
- 默认工时解析优先级：**枪名所在台账表的表级专用规则（超管覆盖值 → 系统内置值）→ 按枪名机型 C/X 的回退规则 → 固定兜底（确认图 2h / 确认图修改 0.75h / 设计 3h）**。枪名机型取枪名首个「-」前一个字符（如 `SRTC-...` → C）。
- 系统内置各默认分类常用表（X2C/SRTC、PSW/UC、ROBOT/RTC、TOYOTA/C01-C10 等）的专用工时；支持「恢复本分类内置规则」与「全部恢复内置」。
- 保存经 `PUT /api/system/settings` 写入 `tableGunHours`（回退规则写 `defaultGunHours`，固定任务工时写 `extraTaskHours`），立即生效。
- 生效场景：主页面任务编辑模态框新增/修改枪名时自动填充工时（仅覆盖自动填充值，手动输入值保留）；切换任务内容时按新内容重算已填枪名的工时；焊枪台账「任务分配模式」批量创建确认图任务。

#### 导入与导出

- **分类导出**（页面入口）：选择一个或多个分类导出；单个分类导出为单个 `.xls` 工作簿，多个分类打包为 `.zip`（每个分类一个独立 `.xls`）。每张表对应工作簿中的一个工作表，列顺序为「序号/焊枪名/客户/时间/担当/备注」，表头蓝色、斑马纹、完整边框。
- **系统设置 → 数据管理 → 焊枪编号台账**：按分类导入/导出。导入时工作簿内的每个工作表会成为目标分类下的一张表，并**覆盖目标分类下全部表**；目标分类不存在时自动新建。导入仅超级管理员可用。
- **每日编号台账导出**（系统设置 → 数据库维护）：开启后每日定时将全部焊枪编号台账分类打包为一个 `.zip`（每个分类一个独立 `.xls`，文件名 `gun-ledger-all-YYYYMMDD-HHmmss.zip`），独立保留天数与目录可配置（默认 30 天，目录 `backups/gun-ledger-exports/`）。

#### 任务分配（批量创建确认图任务）

- 管理员打开表（持有表级编辑锁、非只读模式）后，可勾选表格右上角的「启用任务分配模式」，此时每行行首出现复选框，勾选需要分配的焊枪名。
- 勾选后点击「为这些枪名分配确认图任务（N）」打开分配面板：选择目标设计人员与日期（默认今天）后确认提交。
- 系统按客户将选中的焊枪名分组（客户为空归入「未命名」），每组生成一条任务（任务名 `<客户> 确认图`）批量创建到指定设计人员的指定日期（`POST /api/tasks/item/batch`）；组内每个焊枪名作为任务的枪名行，枪名工时按默认工时规则解析（优先级：枪名所在台账表的表级专用规则 → 按枪名机型 C/X 的系统回退规则 `defaultGunHours.confirm` → 固定兜底 2h；见下文「默认工时规则」），任务工时为枪名工时之和。
- **相同仕样号合并（添加到已有任务）**：选定设计人员与日期后，系统会拉取该人员当月的任务，找出目标日期下任务名含「确认图」且不含「确认图修改」、且仕样号与所选行的客户名中的仕样号相同的已有任务。若命中，分配面板显示琥珀色提示「发现 N 个相同仕样号的确认图任务，勾选后选中的枪名将**添加到已有任务**，不再新建」；勾选后（命中多条时可进一步选择添加到哪一个）这些枪名通过 `PUT /api/tasks/item`（`field=guns` 追加 + `field=hours` 重算总和）合并进已有任务，其余未命中的分组仍按上述规则新建。
  - 完成提示区分三种情况：「已将 N 个枪名添加到 M 个已有的相同仕样号任务」/「已创建 N 个确认图任务，并将 M 个枪名添加到 K 个已有任务」/「已为 XXX 创建 N 个确认图任务」。
- **已被主任务使用的焊枪名（天蓝色）不显示勾选框**，避免重复分配。
- 任务标记颜色默认浅绿（`#86efac`）；开启系统设置「焊枪台账分配任务标记颜色随机」后从预设颜色中随机选择。
- 创建成功后自动刷新已用枪名标识（天蓝色）并通知其他客户端刷新任务数据；离线时禁止提交。
- 切换表、进入只读模式或离线时会自动退出任务分配模式并清空勾选。

#### 离线模式

- 后端断开时页面顶部显示橙色横幅「此页面禁止编辑」，所有写操作（保存行、新增表、删除、导入等）被拦截并提示「当前离线，禁止编辑」。
- 离线期间所有管理类弹窗自动关闭，表保持只读可打开。
- 网络恢复后自动重新拉取台账数据并重新申请当前表的编辑锁。

### 设计规范知识库

设计规范知识库页面（`/design-standards`）基于本地 Docker 部署的 [Tencent/WeKnora](https://github.com/Tencent/WeKnora) 知识库（问答走 DeepSeek API、向量化走智谱 API），提供三个功能标签：

- **规范检索**：关键词检索知识库中的规范条款，显示命中方式（向量检索/关键词等）与相关度得分；
- **智能问答**：基于检索结果流式生成回答（SSE），并附带引用出处；
- **知识库管理**（一般管理员及以上）：按知识库 ID 关联/取消关联知识库，并只读查看各库文档清单与解析状态。

#### 知识库关联

- 知识库不再自动发现，需显式关联：在 WeKnora 控制台（http://localhost/platform/knowledge-bases）打开目标知识库并复制其 ID，回到本页面「知识库管理 → 关联知识库」粘贴 ID，后端校验通过后保存到项目数据库（`settings.designStandardsLinkedKbIds`）。
- 取消关联仅移除本系统的关联记录，**不会删除 WeKnora 中的知识库**；文档的上传、删除等管理操作统一在 WeKnora 控制台进行。

#### 检索/问答范围

- 「规范检索」与「智能问答」各有一个**知识库范围多选下拉框**，从已关联知识库中勾选；未勾选时无法提交（红色提示），支持全选。
- 下拉项显示文档篇数；接入多个工作空间时，每个库带紫色工作空间标签。
- 问答范围变更后自动开启新会话，避免沿用旧会话的检索范围。

#### 多工作空间（多租户）

- WeKnora 的 API Key 按工作空间隔离，一个 Key 只能访问所属空间的知识库。后端支持配置多个 Key：主 Key `WEKNORA_API_KEY` + 其他空间 Key `WEKNORA_EXTRA_API_KEYS`（英文逗号分隔）。
- **规范检索支持跨工作空间**：后端按空间分组并行检索，合并后按相关度排序。
- **智能问答不支持跨工作空间**：WeKnora 会话是空间级资源；所选知识库跨越多个空间时显示琥珀色提示并禁用发送，后端在 SSE 建连前返回 `400`（`WEKNORA_MULTI_TENANT`）。
- 状态接口返回每个工作空间（Key）的可达性；某个 Key 失效时页面提示「部分工作空间无法访问」，不影响其他空间。

#### 答复约束提示词（仅超级管理员）

- 超级管理员可在页面底部「答复约束提示词」面板中按知识库配置系统提示词（支持 Markdown，可直接粘贴整篇 `.md` 或从文件导入，单条最长 20000 字符）。
- 仓库内置一份焊枪选型提示词模板 [`weknora/knowledge/焊枪选型规范答复约束提示词.md`](weknora/knowledge/焊枪选型规范答复约束提示词.md)，可直接复制粘贴到对应知识库的提示词输入框使用。
- 保存后后端在该知识库所属工作空间创建/更新一个绑定 KnowledgeQA 模型的**自定义智能体**，问答由该智能体承载，提示词完全替换 WeKnora 默认提示词；引用出处仍由系统单独渲染，不受影响。
- 一次问答选中多个知识库时，取所选范围内第一个已配置提示词的库生效；清空提示词会同步删除对应智能体；未配置提示词的知识库保持默认行为。

查看权限与工时管理页面一致（`settings.designStandards`），超级管理员可在页面底部配置一般管理员/普通用户的访问权限。WeKnora 的地址与 API Key 仅保存在后端 `backend/.env`（`WEKNORA_*`），前端统一经 `/api/design-standards/*` 代理访问。部署物料与文档全部内置在仓库 `weknora/` 目录（详见 [weknora/README.md](weknora/README.md) 与 DEPLOYMENT.md）。

### 系统设置

系统设置页面包含「数据管理」「数据库维护」「登录管理」「日志管理」「计划管理」五个标签页。其中「数据库维护」「登录管理」「日志管理」「计划管理」仅超级管理员可见；「数据管理」对一般管理员的开放程度由系统设置页面权限控制。

#### 数据管理

- **任务管理**：导出渲染后的任务 `.xls` 表格，文件名格式为 `obara-tasks-YYYY-MM-DD-HHmmss.xls`；导入任务数据时必须使用系统导出的 `.xls` 格式，每次只能选择一个月份覆盖导入。导入只解析任务内容/工时列，`当日合计` 和 `月总工时` 不导入，由系统重新计算。导入月份天数与表格天数不一致时，多出来的日期列会被截断，缺少的日期会按空数据处理。导入表格中新增的设计员不会自动创建，会跳过并在结果中提示。导入仅超级管理员可用；导出超级管理员始终可用，一般管理员需在系统设置权限中放行（仅导出，不能导入）。
- **状态跟踪表**：按筛选条件导出状态追踪数据为 `.xls`（导出入口在状态追踪页面），文件名格式为 `status-tracking-YYYYMMDDHHmmss.xls`。仅超级管理员可导入，支持「仕样号 + 添加时间月」重复检查和覆盖导入选项。
- **工时管理表**：按月份导出工时汇总数据为 `.xls`，文件名格式为 `work-hours-YYYY-MM.xls`。导出表格包含设计员、总工时、工作日工时、周末加班工时、出差工时、请假工时等列，按总工时倒序排列，冻结首行和首列。工作日工时和周末加班工时按主页面日期覆盖规则计算。
- **焊枪编号台账**：按分类导入/导出焊枪编号台账。导出时选择 1 个分类下载单个 `.xls`（每张表一个工作表），选择多个分类时打包为 `.zip`。导入时工作簿内的每个工作表会成为目标分类下的一张表，并覆盖目标分类全部表（目标分类不存在时自动新建）；导入仅超级管理员可用，导出受焊枪台账页面权限控制。

#### 数据库维护（仅超级管理员）

- 自动维护开关：启用自动维护、每日数据库备份、每日任务表格导出、每日编号台账导出、年度任务清理、断网自动备份。
- 可配置最多两个每日执行时间点（默认 `00:30` 和 `12:30`，至少保留一个）、备份保留天数、任务导出保留天数、编号台账保留天数、断网备份保留天数、年度检测月份、月初检测天数、任务保留年数。
- 可配置数据库备份目录、任务导出目录、编号台账导出目录、年度永久归档目录、断网备份目录。
- 手动维护操作：立即备份数据库、立即导出任务数据、立即导出编号台账、清理过期备份、执行年度清理检测、清空所有日志。
- 运行状态显示调度器下次执行时间（取多个时间点中最近的一次）、数据库与各备份目录绝对路径。
- 显示最近数据库备份、最近任务导出、最近编号台账导出、年度永久归档、最近断网备份各 5 个文件。
- 年度清理会先将待删除数据永久归档；断网备份在服务器关闭时（Ctrl+C、SIGTERM）自动触发。
- **数据库备份为单地址**：手动「立即备份数据库」与每日定时备份均只写入配置的数据库备份目录（默认 `backups/database/`），不再复制到任何网络共享地址；如需异地留存，请由运维侧对备份目录做独立的同步/归档。

#### 登录管理（仅超级管理员）

- 可配置多设备同时在线、「允许登录用户修改本人设计计划完成状态」与「允许用户自主改密」三个开关。该完成状态标记开关默认开启；开启后，普通登录用户可在本人同名设计员的设计计划任务上标记任务完成/未完成。
- 「允许用户自主改密」（`allowUserChangePassword`）默认**关闭**：关闭时所有用户调用 `POST /api/auth/change-password` 均返回 `403`（「系统已禁用自主修改密码，请联系管理员」），主页面右上角的用户姓名改密入口也不显示，需要改密时由超级管理员在管理后台重置；开启后登录用户可点击右上角用户姓名自行修改密码（仍需输入当前密码，5 次/15 分钟限流）。
- **IP 黑名单**：拦截异常来源访问。支持精确 IP（`192.168.1.100`）、CIDR 网段（`10.0.0.0/24`）和 IPv4 通配符（`192.168.*.*`）三种规则格式，可一次粘贴多条（逗号/空白分隔，单次最多 50 条，总量上限 500 条），可附备注；界面会列出最近登录失败的 IP（排除已封禁的）供快捷填入。启用后命中规则的 IP 访问任何接口都会收到 403，其登录尝试会以「IP 已被列入黑名单」记录在登录日志中；本机回环地址（localhost）永不拦截，规则修改后立即生效。

#### 日志管理（仅超级管理员）

- 主页面显示最新 10 条管理员（超级管理员和一般管理员）的登录记录，包含账号、姓名、角色、IP、浏览器信息和结果。
- 点击「详细日志」进入操作日志页面（`/system-logs`），可查看所有用户的所有操作记录，支持按用户名、操作类型、HTTP 方法、IP、日期范围筛选，并支持导出 `.xls`。
- 操作日志记录已登录用户的**数据变更与敏感操作**（写操作全记；读取只记导出与数据库统计；会话心跳与页面初始化读接口不记），包含操作描述、方法、路径、IP、浏览器信息、状态码、耗时等，默认最多保留 5000 条（可在「系统设置 → 日志管理」中调整，取值范围 100 ~ 100000，超过上限自动清理最旧记录）。
- 登录日志独立保留，最多 2000 条（不可配置）。
- 操作类型和描述均为中文，例如「添加任务」「更新任务」「移动任务」「重新排序设计员」「批量替换任务」等。
- 浏览器信息存储浏览器名称和版本号、操作系统和版本号、设备类型，但页面和导出表格中仅显示浏览器名称（如「Chrome」）。

#### 计划管理（仅超级管理员）

- 仕样号位数：设置全局仕样号位数（5 位或 6 位），影响主页面纳期提取、任务报表仕样进度搜索、状态追踪添加记录等所有仕样号输入与校验。默认 5 位，切换后立即生效并同步到所有页面。
- 设计计划标记颜色随机：开启后主页面新增任务的默认标记颜色不再固定为浅绿（`#86efac`），而是从预设颜色中随机选择（不含「无」）；默认关闭，保存后立即生效。

## 权限模型

### 超级管理员 `superadmin`

- 查看和编辑所有任务。
- 管理设计人员、一般管理员和普通用户（包括禁用/启用账号）。
- 配置任务报表、工时管理、状态追踪、焊枪台账和系统设置。
- 导入导出系统数据（任务管理、状态跟踪表、工时管理表、焊枪编号台账）。
- 管理焊枪台账分类、表、行，配置按表焊枪名生成规则、执行台账初始化（焊枪名初始化/批量初始化）、管理默认担当人员、配置默认工时规则（按表专用工时、机型 C/X 回退工时与设计变更/既制审图的固定工时）。
- 关联/取消关联设计规范知识库，配置答复约束提示词。
- 查看最新管理员登录信息和详细操作日志。
- 配置多设备同时在线等系统设置。
- 强制重置任意用户密码（重置后旧会话立即失效，账号可直接用新密码登录；也可在登录用户列表中批量重置密码，新密码仅展示一次）。重置**本人**密码时需在弹窗中验证当前密码。

### 一般管理员 `admin`

- 查看和编辑任务。
- 管理设计人员。
- 创建普通用户作为登录用户。
- 配置和管理组长规则、工厂规则（工厂规则重置为默认仅超级管理员）。
- 可新增/重命名/重排焊枪台账分类与表、编辑行（打开表时获取表级独占编辑锁），但**不能删除分类或表**（会被拦截并提示需超级管理员权限）。
- 可关联/取消关联设计规范知识库并查看各库文档清单（文档的上传与删除在 WeKnora 控制台操作）。
- 是否可进入任务报表、工时管理、状态追踪、焊枪台账，取决于对应页面的“一般管理员”开关。
- 是否可进入系统设置数据管理模块，取决于系统设置页面的“一般管理员”开关（仅可查看导出，不能导入）。

### 普通用户 `user`

- 登录后可查看主页面，**但不能新增、编辑、删除、拖拽移动或复制任务**：主页面唯一的编辑门禁是「管理员且非离线」，普通用户在主页面只能浏览，以及在满足条件时对本人同名设计员的设计计划任务标记完成状态（见「主页面 → 颜色标记功能」）。
- 首次登录需修改密码；一般管理员修改自己密码后下次登录需再次修改。被超级管理员重置密码（单个或批量）后旧会话立即失效，可直接用新密码登录。任何角色通过用户管理接口修改本人密码均需提供当前密码（与「修改密码」接口同等防护，限 5 次/15 分钟）。
- 是否可进入任务报表、工时管理、状态追踪，取决于对应页面的“普通用户”开关。
- 是否可进入焊枪台账，取决于「焊枪台账」页面的“普通用户”开关；开启后为只读模式（仅可浏览分类/表/行，不申请表级锁，无任何编辑入口）。

> 权限判定的叠加规则：上述角色权限仅在**在线**时生效。任何角色在离线模式下都会被降级为只读——管理员的任务编辑、枪名移动、标记颜色、撤销/重做等入口一并隐藏，快捷键也只提示「当前离线，禁止编辑」。

## 数据存储

系统使用 **SQLite** 保存数据，默认文件为 `backend/data.db`（WAL 模式，运行时伴随 `data.db-wal` 和 `data.db-shm`）。数据以集合方式存储，主要集合：

| 集合 | 说明 |
|------|------|
| `users` | 登录用户列表，包含 `forcePasswordChange` 字段用于强制修改密码，以及登录时间字段 `lastLoginAt`（本次登录时间）与 `previousLoginAt`（上次登录时间，供页脚「上次登录」展示） |
| `designers` | 设计人员列表，字段含 `name`、`group`、`order`、`hidden`（隐藏后不出现在主页面「全部」与分组筛选中） |
| `statusTrackingItems` | 状态追踪记录 |
| `gunLedger` | 焊枪编号台账，包含 `categories`（分类→表→行三级结构）和 `defaultResponsiblePersons`（默认担当人员） |
| `settings.leaderboard` / `workHours` / `statusTracking` / `gunLedger` / `designStandards` / `systemSettings` | 各页面访问权限：`{ enabled, allowAdmins, allowViewers }` |
| `settings.maintenance` | 数据库自动维护配置（备份/导出/清理开关、保留天数、执行时间点与目录） |
| `settings.workdayOverrides` | 工作日覆盖规则：`{ 'YYYY-MM-DD': 'workday' \| 'weekend' }` |
| `settings.leaderRules` / `settings.factoryRules` | 组长规则、工厂规则（营业担当→工厂映射与默认工厂） |
| `settings.designStandardsLinkedKbIds` | 已关联的 WeKnora 知识库 ID 列表 |
| `settings.designStandardsPrompt` | 答复约束提示词：`{ enabled, knowledgeBases: { [kbId]: { prompt, agentId, updatedAt } } }` |
| `settings.ipBlacklist` | IP 黑名单：`{ enabled, entries: [{ id, ip, note, createdAt, createdBy }] }` |
| `settings.system` | 系统设置，包含多设备登录（`allowMultiDevice`）、允许登录用户标记本人设计计划完成状态（`allowUserDesignPlanColorMark`，兼容字段 `allowUserEditOwnTaskColor`）、允许用户自主改密（`allowUserChangePassword`，默认 `false`）、仕样号位数（`specNumberDigits`）、操作日志保留条数（`auditLogMaxRows`）、设计计划标记颜色随机（`randomDesignPlanColor`）、焊枪台账分配任务标记颜色随机（`randomAssignmentColor`）、默认工时（`defaultGunHours` 机型 C/X 回退值、`tableGunHours` 按台账表的专用工时覆盖、`extraTaskHours` 设计变更/既制审图的固定工时） |

> `settings.system` 各开关的缺省值：多设备登录默认开启，完成状态标记默认开启，自主改密默认关闭，仕样号位数默认 5，操作日志默认最多 5000 条，两个颜色随机开关默认关闭；默认工时缺失时按内置默认值补齐。

除上述键值集合外，三类高写入量数据存放在独立的关系表中，避免整库 JSON 反复序列化：

| 表 | 说明 |
|----|------|
| `task_sheets` / `task_entries` | 任务工时表：每张工时表一行（`designer_id + year + month` 唯一索引），任务条目按行存放（条目级 JSON），写入只重写受影响的单张表；对外接口的 sheet 数据形状不变 |
| `login_logs` | 登录日志独立表，最多保留 2000 条（超限自动清理最旧记录） |
| `audit_logs` | 操作日志独立表，默认最多保留 5000 条（超限自动清理最旧记录；保留条数可在系统设置 → 日志管理中调整） |

建议定期通过 `POST /api/system/maintenance/backup` 备份数据库，也可以通过系统设置导出 `.xls` 作为任务数据的补充备份。

## 键盘快捷键

主页面支持以下键盘快捷键：

| 快捷键 | 功能 | 提示信息 | 生效范围 |
|--------|------|----------|----------|
| `Ctrl+C` | 复制选中的任务 | "粘贴已准备" | 任务获得焦点时 |
| `Ctrl+X` | 剪切选中的任务 | "剪切已准备" | 任务获得焦点时 |
| `Ctrl+V` | 粘贴任务 | "任务已复制" | 任务获得焦点时 |
| `Delete` | 删除当前聚焦的任务 | - | 任务获得焦点时 |
| `Delete` | 删除全部已选中的任务（多任务批量删除） | - | 全局（未打开模态框、焦点不在输入框时） |
| `Ctrl+Z` | 撤销操作 | "暂无可撤销操作"（无操作时）/ "操作已撤销"（成功时） | 全局 |
| `Ctrl+Y` | 重做操作 | "暂无可重做操作"（无操作时）/ "操作已重做"（成功时） | 全局 |
| `Ctrl+Shift+Z` | 重做操作（与 `Ctrl+Y` 等价） | 同 `Ctrl+Y` | 全局 |
| `Ctrl` 连按两次 | 定位到今日任务（等同点击左下角状态圆点，仅滚动不刷新） | "当前不在本月视图，无法定位今日任务"（非本月视图时） | 全局（两次间隔 400ms 内） |
| `Shift` × 2 | 快速添加「确认图修改」：搜索枪名 → 默认带出该枪名所属任务的设计员 → 安排到某天任务 | - | 仅管理员；两次间隔 400ms 内；光标在输入框内或弹窗已打开时不触发 |
| `Esc` | 关闭批量操作弹窗 / 任务编辑模态框，并结束当前单元格编辑 | - | 全局 |
| `F11` | 全屏 / 退出全屏（按键被拦截改走 Fullscreen API，与页脚按钮状态同步） | - | 主页面全局 |

说明：
- 所有快捷键同时接受 `Ctrl` 与 `Cmd`（Mac），上表统一写作 `Ctrl`（「连按两次 `Ctrl`」例外，见下条）。
- `Ctrl+C`/`Ctrl+X`/`Ctrl+V` 与单任务 `Delete` 绑定在任务元素上，需要先点击/聚焦到某个任务才生效；`Ctrl+Z`/`Ctrl+Y`/`Ctrl+Shift+Z`/`Esc`/全局 `Delete`/连按两次 `Ctrl` 是 window 级监听。
- 连按两次 `Ctrl` 的判定会在两次之间按下其它键（如 `Ctrl+C`）或按下鼠标（`Ctrl`+单击多选、`Ctrl`+拖拽复制）时立即打断并重新计数，因此不会与录入类快捷键冲突。**该快捷操作只认物理 `Ctrl` 键，Mac 上连按两次 `Cmd` 不生效**（其余快捷键仍同时接受 `Ctrl` 与 `Cmd`）。
- 离线或非管理员时，撤销/重做等编辑类快捷键只提示"当前离线，禁止编辑"或不做处理。
- 选中任务后，按住 `Ctrl` 可选择多个任务。
- 多选任务支持拖拽移动、剪切、复制、粘贴。
- 按住 `Ctrl` 键拖拽任务到目标单元格，会执行批量复制操作而非移动操作（落点规则见「主页面」章节）。
- 同一用户最多保留 10 步撤销记录和 10 步重做记录。
- `Delete` 删除操作也可通过 `Ctrl+Z` 撤销。
- 其他常见提示原文：`请先复制任务`、`剪切失败`、`粘贴失败`、`无法撤销此操作`、`无法重做此操作`、`撤销失败`、`重做失败`。

## 仕样信息搜索

系统支持从共享目录读取仕样书 PDF 文件，提取纳期和详细信息：

- 搜索路径：通过 `SPEC_SHARE_PATH` 配置（如 `\\server\仕样书$`）；未配置时代码回退到内置地址 `\\192.168.160.6\仕样书$`
- 支持按仕样号搜索（位数由系统设置 `specNumberDigits` 控制，5 或 6 位），自动查找最新版本（如 `12345.PDF`、`12345.01.PDF` 等）
- 可提取纳期、中间商、最终客户、项目名称、数量、营业担当等信息
- 纳期获取超时时间为 9 秒，完整信息获取超时时间为 15 秒
- **注意**：仕样书共享路径可在 `backend/.env` 中通过 `SPEC_SHARE_PATH` 修改，修改后需重启后端服务。

### 仕样书 PDF 专用解析规则

`backend/utils/specPdfParser.js` 实现了**7 类客户仕样书的专用解析规则**，覆盖了仓库内置样本 PDF 的全部类别。各类别表格标签与值单元格的对应关系不完全相同，通用标签匹配规则无法正确取值，因此采用「先匹配专用类别，未命中时回退通用规则」的解析优先级：

| 类别标识 | 仕样书标题关键词 | 样本文件 |
|----------|------------------|----------|
| PSW GUN | `PSW GUN` | `57475.04.PDF`、`57597.01.PDF` |
| SERVO GUN | `SERVO GUN` | `55526.03.PDF`、`56750.03.PDF`、`56956.02.PDF`、`56985.03.PDF`、`57048.01.PDF`、`57157.01.PDF`、`57195.03.PDF` |
| GM Lean Series GUN | `GM Lean Series GUN` | `55606.03.PDF` |
| GM GLOBAL GUN | `GM Global GUN` | `57908.02.PDF` |
| 焊钳修改 | `焊钳修改` + `客户仕样书` | `55862.03.PDF`、`56735.02.PDF`、`57153.01.PDF` |
| IT GUN | `IT GUN` | `57868.02.PDF` |
| EQ GUN | `EQ GUN` | `57278.03.PDF` |

解析逻辑（各类别共性）：
- **仕样号**：从含「状态标记」的行中提取，格式为 `状态标记\t<仕样号> <版本> 1N`；
- **纳期 + 数量**：从状态标记行之后的第一个日期行（`yyyy-mm-dd` 格式）中同时提取；
- **中间商**：状态标记行之后、纳期行之前的值行（若该行以 11 位以上电话号码开头则为联系人，无中间商）；
- **最终客户 / 营业担当**：各类别按各自的锚点行定位（如 SERVO GUN 通过「最终客户」行、GM GLOBAL 通过「客户名称」行）。

**回退机制**：未命中以上 7 类，或专用规则解析不到仕样号时，自动回退到通用标签匹配规则（按字段标签如「纳期」「客户名称」逐一搜索取值）。通用规则可覆盖部分格式规范的仕样书，但对表头标签与值单元格顺序不对应的特殊类别会解析失败。

## 强制修改密码

系统支持首次登录强制修改密码机制：

- 新建登录用户首次登录时必须修改密码（首次启动自动创建的超级管理员同样如此）。
- 超级管理员重置用户密码（管理后台单个重置或批量重置）后，账号可直接用新密码登录（不强制改密），但旧会话会立即失效，旧会话下次操作时提示「密码已被管理员重置，请使用新密码重新登录」。
- 一般管理员在管理后台修改自己的密码后，下次登录需修改密码。
- 通过 `PUT /api/users/:id` 修改**本人**密码（含超级管理员在管理后台重置自己的密码）必须提供当前密码（`oldPassword`），校验失败返回 400，并按用户 ID 限流 5 次/15 分钟——与 `/api/auth/change-password` 同级防护，防止被盗 Token 直接改密接管账号；超级管理员重置**他人**密码无需当前密码。该接口不受「允许用户自主改密」开关限制。
- 已存在的非超级管理员账号在系统升级后会自动标记为需要修改密码。
- **API 层强制拦截**：`forcePasswordChange` 标记未清除前，除「修改密码」和「退出登录」外的所有 API 调用一律返回 `403`（`code=FORCE_PASSWORD_CHANGE`），防止绕过前端页面直接调用接口。
- 修改密码页面为 `/change-password`，未提示修改密码时访问会自动跳转回主页。强制改密页面使用的是 `POST /api/auth/change-password` 接口，该接口受「允许用户自主改密」开关控制——若该开关处于关闭状态（系统默认），处于强制改密流程的账号将无法通过该页面完成改密。因此**启用强制改密的系统应同时在系统设置中开启「允许用户自主改密」**，或由超级管理员通过用户管理接口代为处理。

## 操作日志

审计日志回答的是「谁改了什么」，而不是「谁打开了页面」，因此记录范围按「是否改变状态」收敛（`backend/middleware/auditLog.js` 的 `shouldAudit`）：

- **写操作全记**：`POST` / `PUT` / `PATCH` / `DELETE`。
- **`GET` 只记敏感读取**：各类导出（路径以 `/export`、`/export-all`、`/export-xls` 结尾）与 `GET /api/system/db-stats`。
- **常规读接口不记**：工作台每次刷新会并发十余个初始化 `GET`（设置、列表数据、版本信息等），这些不再入库，真正的增删改不会被读请求淹掉。
- **会话心跳不记**：`GET /api/auth/validate` 每 60 秒一次，与用户操作无关。
- **语义为只读的 `POST` 不记**：`/api/spec/spec-info`、`/api/spec/delivery-date`、`/api/spec/spec-raw-text`、`/api/design-standards/search`、`/api/design-standards/chat`、`/api/tasks/batch-replace/search`、`/api/status-tracking/import/check`。

日志内容与保留策略：

- 日志包含操作描述、HTTP 方法、路径、IP、浏览器信息、状态码、耗时、请求体和响应消息。
- 操作类型和描述均为中文，例如「用户登录」「添加任务」「更新任务」「删除任务」「移动任务」「重新排序设计员」「批量替换任务」「导出任务数据」「导入任务数据」等。
- 浏览器信息存储浏览器名称和版本号、操作系统和版本号、设备类型，但页面和导出表格中仅显示浏览器名称（如「Chrome」）。
- GET 请求不记录响应消息（避免存储大体积任务数据），POST/PUT/PATCH/DELETE 请求记录请求体（脱敏后最大 2000 字符；DELETE 的请求体用于说明「删了谁/删了哪条」，GET/HEAD/OPTIONS 无请求体故不记录）。
- 操作日志默认最多保留 5000 条（可在「系统设置 → 日志管理」中调整），超过自动清理最旧记录。
- 仅超级管理员可在「操作日志」页面查看，支持按用户名、操作类型、HTTP 方法、IP、日期范围筛选，并支持导出 `.xls`。
- 筛选下拉框中的操作类型按拼音排序。
- 仅登录日志查询（`/api/system/login-logs`、`/api/system/admin-login-logs`）与操作日志查询（`GET /api/system/audit-logs`、`GET /api/system/audit-logs/filter-options`）接口本身不记录，避免日志自我膨胀；`GET /api/system/audit-logs/export` 属于导出操作，正常记录；系统设置变更、维护操作等其他接口（如 `PUT /api/system/settings`）均正常记录。
- 系统设置「日志管理」页面顶部展示的管理员登录记录取自 `GET /api/system/admin-login-logs`（仅超级管理员/一般管理员的登录记录，默认 10 条）；完整登录日志查询接口为 `GET /api/system/login-logs`。

## 安全配置

系统使用集中的安全配置文件管理敏感信息，所有配置项均可通过环境变量设置。安全配置集中在 `backend/config/security.js`，包含 JWT 配置、CORS 配置、Gitee API 配置、数据库路径配置和服务器配置。

### 安全增强特性

- **JWT_SECRET 强制校验**：服务启动时强制校验 `JWT_SECRET` 配置，缺失则直接终止启动并输出错误提示。JWT 默认有效期 3 天（`JWT_EXPIRES_IN`），配合服务端会话吊销机制，登出/改密/禁用后旧令牌立即失效。
- **多层 API 限流**：登录接口三层限流（按 IP 15 分钟 300 次兜底防密码喷洒，可用 `LOGIN_IP_RATE_LIMIT_MAX` 调整；按「IP + 用户名」15 分钟 20 次防单账号爆破；再加全局限流），修改密码接口两层限流（按用户 ID 15 分钟 5 次 + 全局 API 限流）；所有 `/api` 接口共享每 IP 15 分钟 3000 次的全局限流（可用 `API_RATE_LIMIT_MAX` 调整，`OPTIONS` 预检与本机环回请求不计数），兼容内网多人共用同一代理出口的场景。超限统一返回 `429`。
- **请求体敏感信息脱敏**：操作日志记录时递归脱敏（支持嵌套对象与数组），字段名匹配 `password`/`passwd`/`secret`/`token`/`api_key`/`apikey`/`authorization`（不区分大小写）一律显示为 `[REDACTED]`。
- **真实 IP 防伪造**：`trust proxy` 设为 `loopback`，仅信任本机回环代理转发的 `X-Forwarded-For`；外部直连请求伪造的 XFF 不会被采信，登录/操作日志的 IP 与限流计数均以 `req.ip`（Socket 对端地址）为准。
- **收敛 CSP 响应头 + CORS 强制白名单**：后端启用 Helmet 内容安全策略（资源仅限同源加载、禁用插件、禁止页面被嵌入框架），作为纵深防御；CORS 为通配符时自动不启用 credentials。**生产环境强制要求显式 CORS_ORIGIN 白名单**，未配置将导致服务启动失败（`security.js` 中直接 `process.exit(1)`），开发环境未配置才允许回退为通配符 `*`。
- **IP 黑名单**：超级管理员可在系统设置「登录管理」中配置精确 IP / CIDR 网段 / IPv4 通配符规则（最多 500 条），命中的来源 IP 访问任意 `/api` 接口一律返回 `403`（`IP_BANNED`）；`OPTIONS` 预检与本机回环地址永不拦截，IPv4-mapped IPv6 会归一为 IPv4 后匹配，防止同一地址换写法绕过。
- **强制改密 API 拦截**：未修改初始密码的用户除「修改密码」「退出登录」外的所有 API 调用一律返回 `403`（`FORCE_PASSWORD_CHANGE`）。
- **路径遍历攻击防护**：仕样书 PDF 路径参数进行严格校验，禁止 `..`、`/`、`\`、`:` 等特殊字符，同时检测 URL 编码（如 `%2e%2e`）和 Unicode 编码（如全角句号 `．．`）等绕过手段，确保只能访问允许的共享目录。
- **密码修改安全**：修改密码接口添加限流（15 分钟内最多 5 次尝试）和参数校验，修改成功后返回新的 JWT Token 并更新 sessionId，使旧 Token 失效。
- **登录失败全量留痕**：登录成功与失败（含用户不存在、密码错误、账号禁用，失败原因记录在 `reason` 字段）均写登录日志，且「用户不存在」与「密码错误」返回相同文案，避免用户枚举。
- **Excel 依赖本地化**：Excel 解析使用随仓库分发的 SheetJS `xlsx@0.20.3`（`backend/vendor/xlsx-0.20.3.tgz`，以 `file:` 协议安装），修复旧版 0.18.5 的原型污染（CVE-2023-30533）与正则拒绝服务（CVE-2024-22363）漏洞，且内网安装无需再从 npm 拉取该包。
- **Socket.IO 认证与角色校验**：WebSocket 连接建立时强制验证 JWT Token，支持从 `socket.handshake.auth.token` 或 `Authorization` 请求头获取令牌，验证失败则拒绝连接。焊枪台账的表级锁申请（`gun_ledger_lock_table`）、行取号（`gun_ledger_start_edit`）与锁心跳（`gun_ledger_table_heartbeat`）事件额外要求 `admin`/`superadmin` 角色，防止普通用户构造客户端抢占编辑锁阻断管理员。同时支持单设备登录限制，当 `allowMultiDevice=false` 时，已登录用户在其他设备登录会使旧连接失效。

详细的环境变量配置、版本检查机制和安全加固建议，请参考 [Windows 部署指南](DEPLOYMENT.md)。

## 前端加载与构建产物

### 路由加载策略

页面按访问频率分为两类，配置在 `frontend/src/App.tsx`：

| 类型 | 页面 | 加载方式 | 说明 |
|------|------|----------|------|
| 静态导入 | 登录 `/login`、主页面 `/` | 随主 chunk 同步加载 | 主页面是首页，静态导入可避免首屏多一次 chunk 往返；改为懒加载反而更慢 |
| 懒加载 | 任务报表、工时管理、管理后台、修改密码、系统设置、操作日志、状态追踪、焊枪台账、设计规范知识库 | `React.lazy` + `Suspense`，进入路由时按需下载 | 首屏不下载这些页面的代码，切换路由时显示「加载中...」占位 |

### 加载态

整页数据加载统一使用 `frontend/src/components/LoadingScreen.tsx`，各页面不再自己写「转圈图标 + 灰字」：

- **中心卡片**：三层 SVG 圆环（淡色整圈轨道 + 蓝色渐变主弧顺时针旋转并呼吸伸长 + 内圈短弧逆时针快转）+ 中心脉动圆点 + 周期性外扩波纹；文字下方是一条不确定进度条（左侧长拖尾渐隐、右端实色做扫描头，光带循环推进）。
- **骨架屏**：由 `skeleton` 参数选择，取值见下表；传 `true` 等同 `'dashboard'`（兼容旧的布尔用法）。骨架与真实页面版式逐项对齐（表头行数、`colgroup` 列宽、卡片结构、行数），目的是数据到位、真实内容替换骨架时布局不发生跳动。
- **防闪**：组件内部延迟 120ms 才渲染内容，数据很快返回时不会闪一下白屏。
- **无障碍与降速**：外层带 `role="status"` 与 `aria-label`；样式集中在 `index.css` 末尾的「加载态」段落，关键动画均纳入 `prefers-reduced-motion` 降速名单。
- **与路由占位的区别**：`App.tsx` 中 `Suspense fallback`（显示「加载中...」）负责 chunk 下载期间的路由切换占位；`LoadingScreen` 负责页面数据加载期间的全屏加载态，两者互不替代。

| `SkeletonKind` | 页面 | 骨架版式 |
|------|------|------|
| `dashboard` | 主页面 | 绿色顶栏（logo / 标题 / 月份胶囊 / 人员下拉 / 导航按钮）+ 排产表（双行表头、分组行、设计员行，日期列按 336px） |
| `statustracking` | 状态跟踪 | 双行蓝色表头 + 斑马纹宽表格，列宽与真实表格 `colgroup` 一致 |
| `leaderboard` | 任务报表 | 蓝 / 绿渐变卡头 + 查询输入区 + 结果卡片占位 |
| `workhours` | 工时管理 | 双列统计卡片（卡头图标 / 开关）+ 人员进度列表 |
| `gunledger` | 焊枪编号台账 | 绿色顶栏 + 左侧表列表 + 右侧绿表头表格 |
| `systemsettings` | 系统设置 | 白顶栏 + tab 栏 + 字段网格卡片 |
| `designstandards` | 设计规范知识库 | 状态卡 + tab 胶囊行 + 检索面板（真实页面各 tab 内容互斥，只还原当前 tab） |

`npm run build` 后 `frontend/dist/assets/` 的典型构成（以下为 2026-10-29 构建的**未压缩**体积，仅作量级参考，会随代码和依赖版本变化）：

### 维护约定

- 新增页面时，除首页外一律使用 `React.lazy` 注册路由，避免主 chunk 膨胀。
- 新增有整页数据加载的页面时，加载态一律用 `LoadingScreen`：在 `LoadingSkeleton.tsx` 里补一个与该页版式对齐的骨架组件、注册到 `SKELETONS` 与 `SkeletonKind`，再于页面的加载分支传对应的 `skeleton` 值。只有局部二次加载（页内某个区域的刷新）才使用区域内的小骨架或转圈，不必做全页骨架。
- 新增体积较大的第三方依赖时，评估是否归入上表某个 vendor 分组（在 `vite.config.ts` 的 `manualChunks` 中补充），避免它与业务代码混在同一个 chunk。
- 主页面（`frontend/src/pages/Dashboard/`）已按「容器 + 组件 + hooks + 纯函数」拆分，新增逻辑优先放入对应子模块，不要继续往 `index.tsx` 堆代码。

## 数据库维护

系统内置自动维护功能，可通过 API 或配置管理数据库备份、任务导出、断网备份和年度数据清理。

### 自动维护

自动维护在每日配置的时间点（最多两个，默认 `00:30` 和 `12:30`，调度器取距当前最近的时间点作为下次执行时间）执行以下任务：

| 任务 | 说明 | 默认状态 |
|------|------|----------|
| 数据库备份 | 使用 SQLite 在线备份 API 生成 `.db` 一致性快照，写入配置的备份目录 | 启用 |
| 任务数据导出 | 导出渲染后的任务表为 `.xls` 文件（`task-export-YYYYMMDD-HHmmss.xls`） | 启用 |
| 编号台账导出 | 将全部焊枪编号台账分类打包为一个 `.zip`（每个分类一个独立 `.xls`），文件名 `gun-ledger-all-YYYYMMDD-HHmmss.zip` | 启用 |
| 过期备份清理 | 删除超过保留天数的旧备份（含数据库备份、任务导出、编号台账导出和断网备份目录） | 自动执行 |
| 年度任务清理 | 在指定月份自动清理超过保留年限的旧任务数据 | 启用 |

### 数据库备份

手动「立即备份数据库」（`POST /api/system/maintenance/backup`）与每日定时备份共用同一备份函数：

- 使用 SQLite 在线备份 API 生成一致性快照（数据库正在写入时也安全），写入配置的数据库备份目录（默认 `backups/database/`），文件名 `db-backup-YYYYMMDD-HHmmss.db`。
- 备份完成后会合并 WAL 并删除伴随文件，目录中只保留单个 `.db`。
- **只写本地备份目录，不再复制到固定网络共享地址**：此前代码内写死的第二备份地址已移除，避免业务数据库副本落在共享盘上长期留存。
- 如需异地/异机留存，请在运维侧对备份目录做独立同步（如计划任务 + `robocopy`），并自行管理该副本的访问权限与保留策略。

### 断网备份

断网备份（offline backup）是服务关闭前的快速备份机制，独立于定时备份：

- 触发时机：后端收到 `SIGINT`/`SIGTERM` 信号（即 `Ctrl+C` 或服务停止）时，会先创建一次断网备份再退出。
- 防抖机制：同一次会话内 5 分钟内只生成一次，避免短时间内重复备份。
- 存储位置：独立目录 `backups/offline/`，便于与日常备份区分。
- 备份文件名：
  - 关闭触发：`offline-backup-shutdown-{YYYYMMDD-HHmmss}.db`
  - 用户触发：`offline-backup-{userId}-{username}-{YYYYMMDD-HHmmss}.db`
- 可通过 `POST /api/system/maintenance/offline-backup` 主动触发：本机环回地址（localhost）可匿名调用（供 stop.bat 等运维脚本），非环回请求须为超级管理员。

| 清理旧任务 | `DELETE /api/system/cleanup/old-tasks?keepMonths=12` | 清理指定月份之前的任务数据 |
| 清理旧状态追踪 | `DELETE /api/system/cleanup/status-tracking?keepMonths=24` | 按保留月数清理旧状态追踪数据 |
| 清理状态追踪记录 | `POST /api/status-tracking/cleanup` | 按时间点清理状态追踪记录，请求体 `{beforeMonth, beforeYear, mode?}`，`mode=delivery` 按纳期月清理，缺省按添加时间月清理 |

### 数据库统计

`GET /api/system/db-stats` 返回数据库统计信息：

- 逻辑数据大小（键值集合与任务条目 JSON 序列化后的字节/KB/MB）
- SQLite 物理存储信息：引擎、驱动、journal 模式，以及 `data.db`/`data.db-wal`/`data.db-shm` 三个文件的大小
- 用户、设计人员、任务、日志等数据条数
- 警告信息（逻辑数据超过 10MB/50MB、数据超过 24 个月，仅为提示非硬限制）

## 维护建议

- 定期通过 `POST /api/system/maintenance/backup` 备份 `backend/data.db`，并在执行升级或批量导入前额外备份一次。
- 生产环境必须修改 `backend/.env` 中的 `JWT_SECRET`，并限制 `CORS_ORIGIN`。
- 公网部署时请确保使用强密码策略，并根据需要关闭多设备同时在线。
- 大批量导入前先在测试环境验证表格格式，确认设计人员列表已提前维护完成。
- 排障时优先查看后端控制台、浏览器 DevTools 网络请求、系统设置中的登录日志和操作日志。
- 监控数据库大小：`db-stats` 中 10MB/50MB 仅为提示性警告而非 SQLite 限制（SQLite 单库上限约 281TB，1GB 以内均可稳定运行），可结合任务月份数决定是否清理旧数据，必要时对数据库执行 `VACUUM` 回收空间。
- 建议启用自动维护，并根据业务需求调整备份保留天数和数据保留年限。

## Windows 服务控制台

系统提供基于 .NET Framework 4.8 的 WinForms 桌面控制台 `control/ObaraServiceController.csproj`，用于在 Windows 上一键管理前后端服务，无需手动开多个命令行窗口。

### 功能

- 服务启停：单独启停后端 / 前端，或一键启动、一键停止。**「一键停止」在后台线程执行**（`taskkill`、等待进程退出与端口探测均为阻塞操作），期间按钮自动禁用，结束后恢复，避免停止过程中界面卡死无响应。
- 实时监控：定时探测前后端端口（默认 2 秒一次），显示进程 PID、端口延迟和运行 / 停止 / 异常状态。
- 进程状态健壮性：进程对象从未成功启动或已释放时访问 `HasExited`/`Id` 会抛异常，控制台对状态读取、退出事件日志、启动失败与释放路径均做了防护（释放前先置空字段、启动失败即释放残留对象），避免误报「后端进程已退出 (PID: 0)」或状态卡片卡在运行中。
- 端口配置：可在界面修改前后端端口并持久化到本地配置（默认后端 `5000`、前端 `5173`）。
- 路径绑定：自动从 EXE 所在目录向上查找 `backend/` 与 `frontend/`，**不硬编码绝对路径**，整个项目目录移动后仍可直接使用。
- 一键打开浏览器：点击「打开浏览器」可直接访问运行中的前端界面。
- 依赖自动安装：首次启动服务时若依赖缺失会自动执行 `npm install`。
- Node.js 环境检测：复用 `ProcessManager` 的健壮发现逻辑（PATH 扫描、`node.exe` 探测、`npm.cmd` 解析和 AppData 回退），检测失败时输出具体原因，避免误报「Node.js 未安装」。
- 日志显示：实时输出前后端子进程日志，支持清空。
- 配置持久化：端口与监控间隔保存在本地配置文件，重启后自动加载。
- UI 风格：暗色科技风（自定义 `ThemeColors`），双缓冲优化，避免鼠标悬停卡顿；标题栏与确认对话框针对高 DPI 优化。

### 构建版本自动生成

控制台版本号**按构建日期自动生成**，无需手工维护：

- 标题栏副标题显示的版本取自 EXE 文件自身的最后写入时间（即链接器写盘时间），每次重新构建自动更新为构建当天日期。
- MSBuild 在每次编译前通过 `GenerateVersionFile` 目标自动生成 `control/Properties/GeneratedVersion.cs`，写入 `AssemblyVersion` / `AssemblyFileVersion` / `AssemblyInformationalVersion` 三个属性（格式 `yyyy.M.d.0`），保证 Windows 文件属性「详细信息」页显示的版本与标题栏一致。
- `AssemblyInfo.cs` 和 `.csproj` 中的版本字段仅保留占位值，构建时会被覆盖。

### 构建产物

| 文件 | 说明 |
|------|------|
| `control/bin/Release/Obara-Task-Management-Service-Console.exe` | 控制台主程序，可直接双击运行 |
| `control/bin/Release/*.config` | 运行时配置文件，随主程序一起分发 |

> 控制台 EXE 不依赖前后端代码，只通过运行进程的方式调用 `npm`/`node`，因此可单独拷贝到任意位置使用，但建议与项目根目录（包含 `backend/` 和 `frontend/`）放在同一目录。

### 本地构建

需要在 Windows 上安装 .NET Framework 4.8（Windows 10/11 自带）。使用 MSBuild 构建：

```bat
cd control
C:\Windows\Microsoft.NET\Framework64\v4.0.30319\MSBuild.exe ObaraServiceController.csproj /p:Configuration=Release /t:Build
```

构建完成后产物位于 `control/bin/Release/`。构建时 MSBuild 会自动生成 `Properties/GeneratedVersion.cs` 写入当日版本号，无需手工修改。`control/.gitignore` 文件用于排除 `bin/`、`obj/` 等中间产物，避免提交到版本库。

### 自动构建

控制台 EXE 由 GitHub Actions 自动构建并发布到 Release，详见下文 CI/CD 章节。

## CI/CD

项目通过 `.github/workflows/build-and-deploy.yml` 实现自动构建与文档部署：先运行变更检测任务（按改动路径过滤），再按需条件执行 EXE 构建和文档部署两个任务。

### 触发条件

- 推送到 `main` 分支，且改动了 `control/**`（触发 EXE 构建）或 `README.md`、`docs/**`、`.github/workflows/build-and-deploy.yml`（触发文档部署）。
- 推送 `v*` 形式的 tag（正式版本）。
- 手动触发（`workflow_dispatch`）。

### 任务一：构建控制台 EXE

- 运行环境：`windows-latest`。
- 自动生成动态版本号：tag 推送时使用 tag 名；常规推送时生成 `vYYYY.MM.DD-beta-N` 形式的版本号，避免重复。
- 自动生成变更日志：取当前提交的提交信息（单条），作为 Release 说明。
- 使用系统自带的 .NET Framework 4.8 MSBuild 构建 `ObaraServiceController.csproj`，并自动写入 `AssemblyInfo.cs` 的版本字段（`AssemblyInformationalVersion` 不带 `v` 前缀）。
- 构建完成后清理 `obj/` 中间产物，并将 `bin/Release/` 打包为 `Obara-Task-Management-Service-Console_<version>.zip`，以 Release Assets 附件形式发布。
- 推送到 `main` 时自动创建 git tag 与 GitHub Release；推送 `v*` tag 时直接创建对应 Release。
- Release 正文包含中文说明、变更日志和功能列表，下载请从 Release 页面的 Assets 获取。

### 任务二：部署文档到 GitHub Pages

- 运行环境：`ubuntu-latest`。
- 将 `README.md` 复制为 `index.md`，连同 `docs/` 目录一起部署到 GitHub Pages。
- 自动创建 `.nojekyll` 以保留原始目录结构。
- 部署完成后可通过 GitHub Pages URL 访问在线文档。

### 版本号规则

| 触发方式 | 版本号格式 | 示例 |
|----------|------------|------|
| 推送 `v*` tag | tag 名 | `v1.2.3` |
| 推送到 `main` | `vYYYY.MM.DD-beta-N` | `v2026.08.19-beta-1` |

> 推送到 `main` 时若当日多次提交，`N` 会自动递增，避免 tag 冲突。
